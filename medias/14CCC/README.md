## 中文信息

**标题**：【中配】分析 30,000+ 个 OpenAPI 规范：Web API 的真实规模到底有多大？

**原标题译文**：Web API 结构与数据模型分析 // Souhaila Serbout // ICSA 2022

这期视频将带你深入探索 Web API 的真实规模与结构特征。通过对 GitHub 上海量的真实数据进行实证研究，我们不再仅仅停留在理论上的 API 设计原则，而是通过对超过 30,000 个真实的 OpenAPI 规范进行量化分析，揭示出当前互联网服务在架构设计、数据模型复杂度以及模式重用方面的核心规律。无论你是正在构建大型微服务架构的工程师，还是负责制定企业级 API 标准的设计师，这期视频提供的客观数据都能为你提供极具价值的参考坐标。

在视频中，我们将详细拆解 API 规模的多个衡量维度。首先是结构规模指标，包括路径数量、操作数量、每条路径的操作数量，以及反映 API 树状结构特征的宽度（根节点直接连接数）和深度（树结构最高深度）。此外，我们还会分析 API 使用的 HTTP 方法种类。在数据模型规模方面，视频将介绍如何定义模式总数、实际使用的模式数量以及每个模式的使用率。通过这些多维度的指标，你可以更清晰地感知一个 API 是属于精简型还是复杂型，以及它在服务粒度上的分布情况。

通过对大量真实数据的分析，视频将展示出一些非常有趣的实证结果。例如，研究发现大多数 Web API 的规模其实并不像想象中那么庞大，大多数 API 的路径数量少于 50 条。与此同时，视频展示了 API 结构中的端点数量与数据模型中定义的模式数量之间存在高度相关性，且实际使用的模式数量与路径数量也呈现出高度的相关特征。此外，视频还会深入探讨 API 内部的数据模式重用情况。研究表明，在大多数 API 中，至少有一个模式是被重用的，并且模式的重用率与数据模型的大小高度相关。这些发现对于优化 API 的可维护性、降低学习难度以及提升开发者使用体验具有重要的指导意义。

视频还会专门针对不同的 API 风格进行细分对比。我们将对比 read-only（仅包含 GET 方法）、RPC（允许使用 POST 写入）、CRUD（典型的读写型）以及 REST 等不同风格下的规模差异。你会发现，read-only 和 RPC 风格往往倾向于小型 API，而 CRUD 和 REST 风格在结构上通常表现得更大。这些差异化的特征能够帮助你在选择合适的 API 风格时，更准确地预估其带来的复杂度变化。

本视频非常适合软件架构师、API 设计师、后端开发人员观看。如果你在设计 API 时经常面临关于服务粒度、数据模型复杂度或 API 管理难题的抉择，这期视频提供的实证研究数据将为你提供客观的参考标准。同时，对于需要了解 Web API 结构特征、数据模型复杂度或 OpenAPI 规范分析的科研人员来说，视频中提到的数据采集过程、指标定义以及从 GitHub 获取并筛选超过 30,000 个模型的研究方法，也将提供非常有价值的学术参考。

看完这期视频后，你将能够掌握一套科学的 API 规模衡量体系，学会从结构和数据模型两个维度去评估 API 的复杂度。你将能够识别出不同 API 风格在规模上的典型特征，理解模式重用与模型大小之间的内在逻辑，并能够基于这些实证数据，在未来的 API 设计和架构规划中做出更科学的决策，从而构建出更符合行业规律、更易于维护和使用的 Web 服务。
